# Data Model: Codec Version Strategies

## Entities

### FormatVersionStrategy *(contract)*

The per-version header-handling contract. One implementation per `FormatVersionRegistry` entry.

| Field | Type | Notes |
|-------|------|-------|
| `decode` | `(FileHeader, int) Function(Uint8List bytes, int offset)` | Parses that version's layout from `offset`; returns header + consumed count. Throws typed `LatchError`s only |
| `encode` | `Uint8List Function(FileHeader header)` | Emits that version's layout. Pure — byte-identical for identical input (FR-005) |

Validation rules: purity (no randomness, no I/O, no platform deps); errors must be existing
typed errors for v1 (FR-009); never emits partial results — a failed decode throws, it does not
return a truncated header.

### Dispatch table

`Map<FormatVersion, FormatVersionStrategy>` — the seam between the registry and the parsers.

- Keyed by the registry's own entries (never by raw integers).
- **Invariant (totality)**: key set == `FormatVersionRegistry.all` value set, both directions.
  Enforced by test (FR-003); a row without a strategy or a strategy without a row is red.
- Private to the façade layer; the public API remains `MyencCodec.decodeHeader` /
  `encodeHeader`.

### MyencCodec façade

The unchanged public entry points.

| Field | Type | Notes |
|-------|------|-------|
| `decodeHeader` | `(FileHeader, int) Function(Uint8List bytes)` | Minimum length → magic → version byte → `require()` gate → dispatch → strategy `decode` |
| `encodeHeader` | `Uint8List Function(FileHeader header)` | Dispatch on `header.version` → strategy `encode` |

Owns exactly the version-independent prefix: length sanity, magic `LATCH` (5 bytes), version
byte (1 byte), registry gate. Nothing version-specific past the prefix.

### FileHeader *(unchanged superset)*

The parsed-header model, unchanged by this feature (FR-010). Version-specific fields of future
versions are optional; consumers check capabilities (BL-001), never `version == n` literals.
v1 fields are as today.

### Header corpus *(new fixture set)*

Committed encoded-hex fixtures generated by the pre-refactor code.

| Field | Type | Notes |
|-------|------|-------|
| shape matrix | zero / one / multiple wraps; encrypted-filename present/absent; boundary chunk sizes; flag variants | Covers v1's structural variety |
| expected bytes | hex strings | Committed outputs of the old `encodeHeader` |

Rule: never regenerated by the new code; edited only when the fixture set is intentionally
extended — an edit during this feature means the refactor leaked behaviour (FR-009).

### Compatibility corpus *(new fixture set)*

Committed full-file artifacts generated by the pre-refactor code.

| Field | Type | Notes |
|-------|------|-------|
| raw files | empty, 1 byte, small, > 1 chunk (multi-chunk tag path), binary | Deterministic seed |
| `.latch` fixtures | one per raw file | Encrypted by pre-refactor code with a known test passphrase |
| manifest | raw-file path → SHA-256 | The expected plaintext hash per fixture |
| negative fixtures | wrong-passphrase, tampered-body | Pin the two non-negotiable failure modes (FR-007) |

Rule: same as the header corpus — pre-refactor artifacts, never regenerated silently.

## State transitions

None — the refactor is stateless. The only "transition" of interest is *acceptance*: a fixture
or freeze file edited during this feature moves the change set from "neutral" to "leaked", and
the correct response is revert, not fix (SC-003).
