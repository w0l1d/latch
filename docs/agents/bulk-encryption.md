# Bulk folder encryption — feature 004 (agent notes)

Read this before touching `lib/core/bulk_plan.dart`, `bulk_settings.dart`, `verified_delete.dart`, `saf_source.dart`, the folder screens, the `keyMode`/`outRelPaths` worker keys, or `packages/myenc_core/lib/src/format/container_sniffer.dart` / `domain/batch_wrap_key.dart`.

Spec: `specs/004-bulk-file-encryption/`.

Pick a folder (optionally recursive) and every file becomes its **own ordinary `.latch` v1 container** — no new format, no archive, `FORMAT.md` untouched. Decrypt takes a folder of containers the same way. The spec carries the requirements; these are the invariants to preserve when editing it.

- **Plumbing, not a new engine.** `lib/core/bulk_plan.dart` (`BulkPlan.enumerate` walks via `DirectoryIoDart`, classifies instead of rejecting; `BulkPlan.preflight` space check; `applyPlacement`) feeds the *existing* `AppCrypto.encryptFiles` / `decryptFiles` and the worker protocol **unchanged**. The worker only gained task keys: `outRelPaths` (parallel to `files`; null = historical flat layout), `keyMode`, `deleteOriginals`/`deleteContainers`, `verifyBeforeDelete`. `file_done` also carries `verified` / `sourceRemoved`. `_resolveOut` honours a relative path only when `outputDir != null`.
- **Containers are recognised by content, never extension** — `sniff()` (`myenc_core/format/container_sniffer.dart`) reads the fixed prefix and returns `container` / `notContainer` / `newerVersion` / `truncated`; it never throws.
- **Shared-KEK mode** (`BulkKeyMode.sharedPerBatch`, `BatchWrapKey`, `myenc_core/domain/batch_wrap_key.dart`): one salt + one Argon2id KEK per run, derived once before the first file and `dispose()`d in the worker's `finally`. **Every file still gets a fresh DEK, secretstream header and wrap nonce**; only the salt/KEK is shared. A batch container must decrypt through the unchanged `EnvelopeService.decrypt` — pinned by `golden_batch_v1.*` (independent Python reference) as well as unit tests. Default is per-file keys; shared is a Settings opt-in (`BulkSettings.keyMode`).
- **Verified deletion is the only way a source is removed** (`lib/core/verified_delete.dart`, `verifyContainerMatchesSource`): re-read the new container, decrypt it (FINAL tag enforced), compare with the source in lockstep, delete only on an exact match; any difference throws `VerificationFailedError` and the original stays. Decrypt mirrors it (`deleteContainers`). In shared mode the verify decrypt still pays Argon2 per file. Never add a delete path that skips this.
- **Placement** (`BulkPlacement`: mirrored folder / beside originals / flat; default from `BulkSettings.outputPlacement`, mirrored; per-run override on the folder screen is **never written back**): `OutputPlanner.planBulk` returns `OutputPlan(outputDir: explicitDir)` off Android and stages + relocates into a grant on Android. Flat rewrites `outRelPath` to the basename and relies on `resolveNameCollision` so same-named files never overwrite. Decrypt passes `allowDownloadsFallback: false` — plaintext is never silently dropped in Downloads. The result screen must say where output went (`bulkSavedWhere`).
- **Teardown sweeps the whole staging tree**, not just the in-flight `.tmp` — staged decrypt output is plaintext. The worker also awaits its write sink before reporting a single-file failure so the partial `.tmp` is gone *before* the failure is visible (a race found by the tampered-container test).
- **Pre-flight order** (main isolate, before the worker spawns): walk → space check (destination **and** Android staging; a `null` free-space reading means *proceed*, never refuse) → >10,000-file confirmation → output planning (may be `OutputPlan.cancelled`). Refusal at any step writes and stages nothing.
- **Android reads the folder through its grant, never its path** (`lib/core/saf_source.dart`). `getDirectoryPath` returns a path and persists no grant, and scoped storage on API 30+ hides non-media files from plain `dart:io`, so a path-picked folder reads as empty and then prompts for a grant on the folder just chosen. Both folder screens therefore pick via `SafBridge.pickTree`, list via native `listTree`, and `SafSource.stage` copies each file to `<cache>/latch_src/<folder>` (`copyToCache`) before the unchanged worker runs; `BulkItem.docUri` / `BulkInventory.sourceTreeUri` carry the origin. The picked grant is passed as `explicitTreeUri`, so there is **no second prompt** (pinned in `output_plan_test.dart`). Rules to keep: staging is all-or-nothing (`SourceStagingError` names the file; nothing is written), `stage` takes `isCancelled` so an abandoned run cannot keep copying after the sweep, `SafSource.sweep` runs on every exit (staged lock-run sources are plaintext), and source deletion is `SafSource.deleteSource` through `removeVerifiedSources(deleteOne:)` — still only after verification, and a refused delete keeps both copies. Cost: cache use doubles for the run. Desktop/iOS keep the path flow (`pickFolder`/`enumerate` seams). Not device-verified yet (quickstart 10–11).
- **Honest limits**: names and the folder structure stay visible (`bulkPrivacyDisclosure` shown on every summary — this is *not* the single-archive protection of 001); `mirroredFolder` on Android needs one tree grant taken at the chosen folder, never one prompt per subfolder; the Save-folders screen lists grants without saying what each was taken for, because Android records no provenance.
- **Testing**: folder screens under `testWidgets` need a tall viewport (`Size(800, 2600)`, DPR 1) or the placement section pushes rows off-screen; real-isolate behaviour is in `test/app_crypto_bulk_test.dart` (plain `test()`, sync file APIs). Kotlin pieces (`SubPathSegments`) are JVM-tested.
